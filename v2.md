# Quickdraw v2 — User Accounts Plan

## Context

Quickdraw today has no persistent identity: players type a name, it lives in `localStorage` (`qd:playerName`), and rooms are identified only by `socket.id`. Matches are discarded the moment a room closes — `RoomManager` deletes the xstate actor on disconnect and there is no database, no HTTP surface, and no auth.

v2 introduces user accounts to unlock five pillars: **personalization** (display name, avatar, holster style synced across devices), **stats** (match history, win rate, reaction times), **friends** (request/accept, invite to a room), **achievements** (catalog + unlocks), and **settings** (server-backed preferences).

Anonymous play stays first-class — the only thing that changes for an anonymous visitor is a "Sign in" link in the app bar. Sign-in is opt-in; it unlocks persistence, not gameplay.

**Question answered**: *Does this require a more robust backend framework?* — **No.** The Railway socket server stays raw Node `http` + Socket.IO. All auth UI and REST endpoints live in Next.js route handlers. The server gains exactly two new concerns: verifying a WorkOS access token on socket connect, and writing one row to Postgres on `gameover`.

## Stack decisions (locked)

| Concern | Choice |
|---|---|
| Auth | WorkOS AuthKit via `@workos-inc/authkit-nextjs` (hosted sign-in/up pages, encrypted session cookies) |
| REST surface | Next.js route handlers (`app/api/**`) |
| Socket auth | `io.use` middleware verifying WorkOS JWTs via JWKS; never rejects, degrades to anonymous |
| Database | Railway Postgres |
| ORM | Drizzle, in a new `packages/db` workspace package shared by `apps/web` and `apps/server` |
| Anon play | Allowed everywhere; auth is opt-in for stats/friends/achievements |
| Phasing | MVP1 = auth + profile + persisted stats + settings · MVP2 = friends · MVP3 = achievements + leaderboard |

## Architecture overview

```
Browser ──cookie session──► Next.js (Vercel) ──Drizzle──► Railway Postgres
   │                            │                                ▲
   │                            └── /api/auth/token              │
   │                                                             │ Drizzle
   └──ws + WorkOS JWT in handshake──► Railway Socket.IO server ──┘
```

- Next.js owns: WorkOS callback, sign-in/out, `/api/me`, `/api/me/stats`, `/api/me/matches`, all UI.
- Railway server owns: live game (unchanged), JWT verification on connect, match persistence on `gameover`.
- `packages/db` owns: schema, migrations, typed queries — imported by both apps.

## Drizzle schema (MVP1 tables)

`users` (keyed by WorkOS user id):
- `id text PK` (WorkOS `user_…`), `email`, `displayName`, `holsterStyle`, `timingMode`, `avatarUrl`, `settings jsonb`, `createdAt`, `updatedAt`. Index on `email`.

`match_results` (one row per finished match):
- `id uuid PK`, `roomCode`, `vsBot`, `startedAt`, `endedAt`, `durationMs`, `totalRounds`
- Per side: `pNUserId` (nullable FK → users.id ON DELETE SET NULL), `pNDisplayName` (snapshot — survives anonymous players and later renames), `pNFinalHp`, `pNAvgReactionMs`, `pNBestReactionMs`, `pNHitRate`
- `winnerSide` ('p1' | 'p2' | null), `rounds jsonb` (array of `RoundRecord`)
- Indexes on `p1UserId`, `p2UserId`, `endedAt`

**Persistence rule**: write the row if at least one side has a `userId`; skip when both are anonymous; bot matches are never persisted in MVP1 (`vsBot` flag reserved).

**Why JSONB for rounds**: rounds are append-only, bounded (≤ ~15), never queried per-shot. One write per match vs N inserts; zero join cost for the history view.

MVP2 adds `friendships` (composite PK `(requesterId, addresseeId)`, enum status: pending/accepted/blocked). MVP3 adds `achievements` (catalog: `code PK`, `title`, `description`, `iconKey`, `rule jsonb`) and `user_achievements` (composite PK `(userId, code)`, `unlockedAt`, `metadata`).

## Auth flow (WorkOS AuthKit)

Env vars (Next.js):
```
WORKOS_API_KEY, WORKOS_CLIENT_ID, WORKOS_COOKIE_PASSWORD (32+ chars)
NEXT_PUBLIC_WORKOS_REDIRECT_URI=http://localhost:3000/api/auth/callback
DATABASE_URL, NEXT_PUBLIC_SERVER_URL
```
Env vars (Railway server): `WORKOS_CLIENT_ID`, `DATABASE_URL`.

- `apps/web/middleware.ts` → `authkitMiddleware({ middlewareAuth: { enabled: true, unauthenticatedPaths: ['/', '/api/auth/:path*'] } })` — root game stays anonymous.
- `apps/web/app/layout.tsx` wraps children in `<AuthKitProvider>`.
- Callback uses `handleAuth({ returnPathname: '/' })`. Sign-in/out are thin redirects to `getSignInUrl()` / `signOut()`.
- Route handlers and server components consume `withAuth({ ensureSignedIn })`.
- **Access token for the socket**: `GET /api/auth/token` returns `{ accessToken }` sourced via `withAuth()` from the encrypted session cookie. Chosen over reading `useAuth()` directly because the hook exposes the user, not the raw token, and using a dedicated route guarantees a fresh value on each connect.

## Socket auth handshake (server side)

New `apps/server/src/auth.ts` using `jose`:
```ts
const jwks = createRemoteJWKSet(new URL(`https://api.workos.com/sso/jwks/${process.env.WORKOS_CLIENT_ID}`));
export async function verifyAccessToken(token: string) {
  try {
    const { payload } = await jwtVerify(token, jwks, { issuer: 'https://api.workos.com' });
    return typeof payload.sub === 'string' ? { userId: payload.sub } : null;
  } catch { return null; }
}
```

In `apps/server/src/index.ts`:
```ts
io.use(async (socket, next) => {
  const token = socket.handshake.auth?.token as string | undefined;
  socket.data.userId = token ? (await verifyAccessToken(token))?.userId : undefined;
  next();   // never reject — degrade to anonymous
});
```

`RoomManager.joinRoom` accepts an optional `userId` and forwards it to the machine. `RoomContext` gains `p1UserId | null`, `p2UserId | null`; `PLAYER_JOINED` event gains `userId?`. No state-machine logic changes.

## Match persistence

- Add `history: RoundRecordJson[]` to `RoomContext`; `settleRound` appends each settled round.
- New action `persistMatch` on `gameover.entry` calls `insertMatch(db, summary)` from `@quickdraw/db`. Aggregates (`avgReactionMs`, `bestReactionMs`, `hitRate`) are computed there from the `history` array.
- Skip the insert when both sides are anonymous. Wrap in try/catch — a DB outage must not crash the room.

Reuse: `computeDamage`, `damageBand`, `isHit` from `packages/game-core/src/utils.ts`; existing `RoundRecord` from `types.ts` is the in-memory shape — the DTO `MatchSummaryDTO` (new) wraps it for boundary crossing.

## REST routes (MVP1)

| Route | Method | Auth | Notes |
|---|---|---|---|
| `/api/auth/{callback,sign-in,sign-out}` | GET | n/a | WorkOS AuthKit helpers |
| `/api/auth/token` | GET | optional | `{ accessToken: string \| null }` for socket handshake |
| `/api/me` | GET / PATCH | required | First GET upserts the row from WorkOS. PATCH body: `{ displayName?, holsterStyle?, timingMode?, settings? }` (Zod validated) |
| `/api/me/stats` | GET | required | Aggregate: `matchesPlayed`, `wins`, `losses`, `winRate`, `avgReactionMs`, `bestReactionMs` |
| `/api/me/matches` | GET | required | `?limit=20&cursor=…` → `{ items, nextCursor? }` |

## Frontend integration (MVP1)

- **Sign-in CTA**: replace right-side block of `apps/web/components/quickdraw/app-bar.tsx` with `<ProfileMenu />` (avatar dropdown when authed, "Sign in" link otherwise). Add an inline "Sign in to track stats" link under the CTAs on `screens/landing.tsx`.
- **`useUser` hook** (new, `lib/quickdraw/use-user.ts`): wraps `useAuth()` + SWR-cached `/api/me`. Returns `{ workosUser, qdUser, loading, refresh }`. SWR for focus revalidation and de-duplication across consumers.
- **`usePreferences` evolution**: anonymous users keep `localStorage` as source of truth (unchanged behavior). Authed users read from `qdUser`; mutations PATCH `/api/me` then `refresh()`. One-shot migration on first authed load: if `qdUser.displayName` is empty and `qd:playerName` exists, PATCH it up.
- **Socket handshake**: new `connectSocket()` helper in `lib/quickdraw/socket-client.ts` fetches `/api/auth/token`, sets `socket.auth = { token }`, then calls `sock.connect()`. `useMultiplayerGame` calls it in place of the direct connect. On `connect_error`, retry once after re-fetching the token.
- **Mid-game sign-in**: deferred — `useMultiplayerGame` does not reconnect while in `holster/arming/drawing/result/gameover`. New `userId` applies on the next room join. Trade-off explicitly accepted: at most one match not credited.
- **Overlay routes**: `app/profile/page.tsx`, `app/settings/page.tsx` are server components that `withAuth({ ensureSignedIn: true })` and render `<ProfileScreen />` / `<SettingsScreen />` with a "Back to game" link. These live outside the in-game phase flow.

## Phasing

### MVP1 — auth + profile + persisted stats + settings (file order)

1. `packages/db` package skeleton + `users` & `matches` schema + queries + initial migration.
2. `packages/game-core/src/types.ts` — `UserId`, `Player.userId`, `MatchSummaryDTO`, `PlayerMatchSide`.
3. `apps/server` — add `jose` + `@quickdraw/db`; add `auth.ts`; wire `io.use`; thread `userId` through `room-manager.ts` + `room-machine.ts`; add `persist.ts` and `gameover.entry` action.
4. `apps/web` — add `@workos-inc/authkit-nextjs`, `swr`, `@quickdraw/db`, shadcn `avatar` + `dropdown-menu`; add `middleware.ts`; wrap layout with `AuthKitProvider`; add `app/api/auth/**` + `app/api/me/**` routes with Zod schemas; add `use-user.ts`; evolve `use-preferences.ts`; evolve `socket-client.ts`; add `profile-menu.tsx` and mount in `app-bar.tsx`; add profile/settings screens + routes; add "Sign in" link on landing.

### MVP2 — friends

`friendships` table; routes `GET/POST /api/friends`, `PATCH/DELETE /api/friends/:id`, `GET /api/friends/requests`; `components/screens/friends.tsx` + `app/friends/page.tsx`; friend entry in `ProfileMenu`.

### MVP3 — achievements + leaderboard

`achievements` + `user_achievements` tables (catalog seeded via migration); routes `GET /api/achievements`, `GET /api/me/achievements`, `GET /api/leaderboard?metric=…&window=…`; screens `achievements.tsx` + `leaderboard.tsx`. **Unlock evaluation** runs server-side inside `persistMatch` after a successful `insertMatch`: `evaluateAchievements(db, userId, summary)` reads the cached rules table, checks each rule against the match + historical aggregates, inserts new `user_achievements` rows on first satisfaction, and emits a new `achievement-unlocked` Socket.IO event to the player if still connected.

- `RoundRecord` and `GameState.history` (`packages/game-core/src/types.ts`) — already populated at gameover, perfect capture point. Nothing new needs to be tracked during play except the new `history` accumulator on `RoomContext`.
- `computeDamage`, `damageBand`, `isHit` (`packages/game-core/src/utils.ts`) — feed match aggregates.
- `qd-*` design tokens in `apps/web/app/globals.css` — profile, settings, friends, achievements screens reuse them; no new palette.

## Non-goals

- No changes to the xstate game state machine or socket event names.
- No migration to Express/Fastify/Nest — explicitly answered above.
- No analytics, logging, or CI changes in this plan.
- No chat, voice, or matchmaking features.
- No mobile-native build.

## Decision log (non-obvious)

1. **Rounds as JSONB on `match_results`** — append-only, bounded, never queried per-shot; one write vs N inserts.
2. **Persist only when ≥1 side authed** — captures partial data for authed users, avoids garbage rows.
3. **Socket auth never rejects** — invalid/stale tokens degrade to anonymous; gameplay never blocked.
4. **Persist on `gameover.entry`, not after rematch/disconnect** — captures matches even if loser drops; avoids double-writes on rematch.
5. **Dedicated `/api/auth/token` route** — `useAuth()` exposes user, not raw token; route guarantees freshness from the encrypted cookie.
6. **No `user_settings` table** — current settings fit in JSONB; promote to a table only if per-setting auditing is required.
7. **`UserId` as branded string** — zero runtime cost, preserves game-core zero-dep invariant, prevents accidental mixing with `socketId`.
8. **Mid-game sign-in defers to next join** — keeps state machine untouched; one match worth of attribution lost in the rare race.
