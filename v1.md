# Quickdraw v1: Multiplayer-Ready Architecture

## Problem

The game runs as a single-page client-only prototype with all logic in one monolithic React hook. Bot AI and real multiplayer share the same code path making server-authoritative timing impossible, the pnpm workspace has no packages/* structure, shadcn components exist but are unused, and localStorage personalization is absent.

## Approach

Restructure into a pnpm monorepo (apps/web, apps/server, packages/game-core). Extract pure game logic into a framework-free package. Wire up a socket.io server that owns phase transitions and shot arbitration for real multiplayer. Bot games remain fully client-side. Migrate screen-level buttons and cards to shadcn primitives while keeping qd-* design tokens unchanged. Add localStorage-based name/holster-style personalization.

---

## System Architecture

```
Browser (apps/web)  ──[socket.io: join-room / client-shot / arm-holster]──►  Socket.IO Server (apps/server)
                    ◄──[socket.io: target-spawn / round-result / player-joined]──

Browser (apps/web)  ──[import]──►  game-core package
Socket.IO Server    ──[import]──►  game-core package

Browser (apps/web)  ──[client-only path]──►  Bot AI (use-bot-game.ts)
Browser (apps/web)  ──[storage]──►  localStorage (qd:playerName, qd:holsterStyle)
```

---

## Decision Log

**DL-001** — Separate socket.io server lives in `apps/server` as a standalone Node.js process  
Next.js custom server couples game engine to deploy lifecycle → horizontal scaling blocked by Next.js single-process model → standalone server can scale independently of the Next.js frontend.

**DL-002** — `packages/game-core` has zero framework or browser dependencies  
Game logic (computeDamage, rollArmingDelay, makeRoomCode, state machine types) is shared by both apps/web (React) and apps/server (Node.js) → any React or browser API import would break the server build → package must be pure TypeScript with no external runtime requirements.

**DL-003** — Bot (vs-AI) games remain fully client-side with no server involvement  
Bot games should work offline and impose zero server load → shot timing is deterministic from rollBotShot which already runs in the browser → routing bot games through the socket.io server adds latency with no correctness benefit.

**DL-004** — Server is authoritative for shot timing and phase transitions in real multiplayer rooms  
Clients cannot be trusted to self-report reaction times when the reaction time is the win condition → a cheating client could claim any timestamp → server receives timestamps from both clients, adjudicates winner, and broadcasts canonical result.

**DL-005** — qd-* CSS variables are preserved as-is when migrating buttons and cards to shadcn  
qd-* tokens are the visual design system source of truth for the game aesthetic → shadcn Button/Card variants are extended with className overrides that reference qd-* tokens → overriding or removing them would change the visual identity.

**DL-006** — shadcn migration covers LandingScreen, InviteScreen, LobbyScreen, and GameOverScreen buttons/cards only  
HpHud, Holster, and TargetSvg have tight animation and geometry coupling that shadcn primitives do not model → migrating them would require significant wrapper complexity for no UX gain → they remain as custom components.

**DL-007** — localStorage keys `qd:playerName` and `qd:holsterStyle` store personalization without server persistence  
No authentication exists → server-side user preferences require an identity system → localStorage provides instant personalization with a clear upgrade path to authenticated profiles later.

**DL-008** — `rollArmingDelay` for real multiplayer rooms is computed on the server and broadcast to both clients simultaneously  
If each client independently rolls the arming delay, the target spawns at different wall-clock times for p1 and p2 → the client that gets a shorter delay gains an unfair advantage → server rolls once and tells both clients when to expect the target.

## M-001 · Monorepo Foundation

Restructure the repository into a pnpm monorepo with `apps/*` and `packages/*` glob patterns. Extract shared types and pure utility functions into a framework-free `@quickdraw/game-core` package. Move the Next.js app into `apps/web`.

### Files

| File | Intent |
|------|--------|
| `pnpm-workspace.yaml` | Declares `packages: ["apps/*", "packages/*"]`. Carries over `allowBuilds`/`ignoredBuiltDependencies` (sharp, unrs-resolver remain excluded). (DL-001) |
| `packages/game-core/package.json` | Name `@quickdraw/game-core`. No runtime dependencies. Exports `./src/index.ts` via exports map. devDependencies: typescript only. (DL-002) |
| `packages/game-core/tsconfig.json` | Extends `../../tsconfig.base.json`. rootDir: src, outDir: dist, composite: true, declarationMap: true. (DL-002) |
| `packages/game-core/src/types.ts` | Phase, HolsterStyle, TimingMode, Player, Target, Shot, RoundRecord, GameState, GameActions — moved from `lib/quickdraw/types.ts`. No React imports, no browser API references. (DL-002) |
| `packages/game-core/src/utils.ts` | makeRoomCode, computeDamage, damageBand, hitInViewBox, rollBotShot, rollArmingDelay, pickP1Name, pickP2Name — moved from `lib/quickdraw/utils.ts`. No `performance.now`, no `document`. (DL-002, DL-008) |
| `packages/game-core/src/index.ts` | Re-exports everything from `./types` and `./utils`. (DL-002) |
| `apps/web/package.json` | Root package.json moves here. Name: `@quickdraw/web`. Adds `@quickdraw/game-core:*` and `socket.io-client`. Keeps all existing deps. (DL-001) |
| `apps/web/tsconfig.json` | Extends `../../tsconfig.base.json`. Keeps Next.js plugin and `@/*` path alias. References game-core via project references. (DL-001) |

### Acceptance Criteria

- `pnpm install` from monorepo root succeeds with no errors
- `packages/game-core` builds with `tsc --noEmit` and no errors
- `apps/web` imports from `@quickdraw/game-core` resolve without `@/lib/quickdraw/*` fallbacks
- No `window`, `document`, `performance`, or React imports in `packages/game-core/src/`

## M-002 · Socket.IO Server

Create a standalone Node.js socket.io server at `apps/server` that manages multiplayer rooms, computes server-authoritative arming delays, adjudicates shot winners, and broadcasts canonical game events to both clients.

### Files

| File | Intent |
|------|--------|
| `apps/server/package.json` | Name `@quickdraw/server`. Deps: `socket.io`, `@quickdraw/game-core:*`. devDeps: `typescript`, `@types/node`, `tsx`. Scripts: `dev` (tsx watch), `build` (tsc), `start` (node dist/index.js). (DL-001, DL-004) |
| `apps/server/tsconfig.json` | Extends `../../tsconfig.base.json`. Module: commonjs. Target: ES2020. OutDir: dist. References game-core. (DL-001) |
| `apps/server/src/room-manager.ts` | `RoomManager` class. `Map<roomCode, RoomState>`. RoomState: `p1SocketId`, `p2SocketId`, `phase`, `round`, `p1Hp`, `p2Hp`, `armingDelayMs`, `targetSpawnedAt`. Methods: `joinRoom`, `leaveRoom`, `getRoom`. Rooms evicted when empty (ephemeral). (DL-004, DL-008) |
| `apps/server/src/game-loop.ts` | `GameLoop` class. Handles client events: `arm-holster` → computes `rollArmingDelay` server-side, broadcasts `target-spawn { armingDelayMs, serverSpawnAt }` to room; `client-shot { reactionMs, dx, dy, targetSize }` → adjudicates winner by comparing both reactionMs values, runs `computeDamage`, broadcasts `round-result { winner, p1Shot, p2Shot, damage, p1Hp, p2Hp }`; `request-next-round` → resets phase to holster. Also handles `player-joined` and `player-left` events. (DL-004, DL-008) |
| `apps/server/src/index.ts` | Entry point. HTTP server on `PORT` env (default 3001). socket.io with `cors: { origin: '*' }` (dev only). Instantiates `RoomManager` and `GameLoop`. Registers `join-room` handler on connection. Graceful disconnect cleanup. (DL-001, DL-004) |

### Socket Event Contract

**Client → Server**

| Event | Payload |
|-------|---------|
| `join-room` | `{ roomCode: string, playerName: string }` |
| `arm-holster` | `{ roomCode: string }` |
| `client-shot` | `{ roomCode: string, reactionMs: number, dx: number, dy: number, targetSize: number }` |
| `request-next-round` | `{ roomCode: string }` |

**Server → Client (room broadcast)**

| Event | Payload |
|-------|---------|
| `player-joined` | `{ name: string, role: 'p1' \| 'p2' }` |
| `player-left` | `{}` |
| `target-spawn` | `{ armingDelayMs: number, serverSpawnAt: number }` |
| `round-result` | `{ winner: 'p1' \| 'p2', p1Shot: Shot \| null, p2Shot: Shot \| null, damage: number, p1Hp: number, p2Hp: number }` |

### Acceptance Criteria

- `pnpm --filter @quickdraw/server dev` starts without error on port 3001
- Two browser tabs can join the same room code
- Both tabs see `target-spawn` at the same wall-clock moment
- The client with the lower `reactionMs` receives `round-result` as winner
- Disconnecting a client sends `player-left` to the remaining client

## M-003 · Client Socket Integration

Split the monolithic `useQuickdrawGame` hook into two parallel hooks — `useBotGame` (client-only, offline-capable) and `useMultiplayerGame` (socket.io-backed, server-authoritative) — both implementing the same `{ state: GameState, actions: GameActions }` interface. Wire `page.tsx` to select the correct hook.

### Files

| File | Intent |
|------|--------|
| `apps/web/lib/quickdraw/socket-client.ts` | Singleton `getSocket()`. Lazy connection to `NEXT_PUBLIC_SERVER_URL` (default `http://localhost:3001`). Typed `ServerToClientEvents` / `ClientToServerEvents` interfaces mirroring the game-loop contract. Disconnects on `window` unload. (DL-001, DL-004) |
| `apps/web/lib/quickdraw/use-bot-game.ts` | Bot-specific paths extracted from original `useQuickdrawGame`. `rollArmingDelay` runs client-side. `rollBotShot` runs client-side. All timers (`armingTimerRef`, `botTimerRef`, `resultTimerRef`) remain in the browser. Returns `{ state: GameState, actions: GameActions }`. (DL-003) |
| `apps/web/lib/quickdraw/use-multiplayer-game.ts` | Real-room hook. Connects via `getSocket()` on mount. Emits `join-room` on `createRoom`. Listens for `player-joined` to populate p2. Listens for `target-spawn`: schedules phase transition to `drawing` using `setTimeout(serverSpawnAt - Date.now())`. On `fire()` emits `client-shot { reactionMs: performance.now() - targetSpawnedAt, dx, dy, targetSize }`. Listens for `round-result` to update HP, history, hudFlash, and advance phase. Phase transitions are server-driven, not timer-driven. (DL-004, DL-008) |
| `apps/web/app/page.tsx` | Reads `?bot=1` search param or local state to select hook. Conditionally mounts `useBotGame` or `useMultiplayerGame`. Passes `state`/`actions` to screen components unchanged. `vsBotShortcut` sets `?bot=1` before triggering `createRoom`. (DL-003, DL-004) |

### Acceptance Criteria

- `/` with no params: multiplayer path; `createRoom` emits `join-room` to server
- `/?bot=1`: bot path; no socket connection opened
- Bot game works with server offline (no network errors)
- In multiplayer: both clients advance to `drawing` phase within 50ms of each other after `target-spawn`

## M-005 · localStorage Personalization

Add a `usePreferences` hook that persists player name and holster style in localStorage. Surface both settings as editable fields on LandingScreen. Display the player name in AppBar.

### Files

| File | Intent |
|------|--------|
| `apps/web/lib/quickdraw/use-preferences.ts` | `usePreferences()` hook. Reads/writes `qd:playerName` (string, default `''`) and `qd:holsterStyle` (`HolsterStyle`, default `'buzzer'`). `useState` initialized from localStorage with SSR guard (`typeof window === 'undefined'`). Setters write to localStorage synchronously. (DL-007) |
| `apps/web/components/screens/landing.tsx` | Name `<input>` pre-filled from `usePreferences().playerName`, calls `setPlayerName` on change, passes name to `onCreate`. Holster style segmented control (buzzer / glow / ring) calls `setHolsterStyle`. (DL-007) |
| `apps/web/components/quickdraw/app-bar.tsx` | Accepts optional `playerName` prop. Displays it in the right slot alongside room code and version badge. Falls back to `1V1 BROWSER DUEL` when empty and no room code is active. (DL-007) |

### Acceptance Criteria

- Typing a name on LandingScreen and reloading the page restores the name
- Changing holster style persists across reloads and applies during game play
- No localStorage access occurs during SSR (no `ReferenceError: window is not defined`)

## Milestone Dependency Order

```
M-001 (Monorepo Foundation)
  └── M-002 (Socket.IO Server)        [depends on game-core package]
  └── M-003 (Client Socket Integration) [depends on game-core package + M-002 contract]
  └── M-004 (shadcn UI Migration)     [independent of M-002/M-003, parallelizable]
  └── M-005 (localStorage Personalization) [independent, parallelizable with M-002/M-003/M-004]
```

M-001 must land first. M-002 and M-003 must be developed together (shared event contract). M-004 and M-005 are independent vertical slices that can proceed in parallel after M-001.

## Invariants

- `packages/game-core/src/` contains no `import` from `react`, `next`, or any browser global (`window`, `document`, `performance`, `navigator`).
- The socket.io server never stores shots in a database — `RoomState` is in-memory and evicted on room empty.
- `rollArmingDelay` is called exactly once per round per room, on the server, and its result is broadcast to both clients before either transitions to `arming` phase.
- `useBotGame` and `useMultiplayerGame` both satisfy the `{ state: GameState, actions: GameActions }` interface — `page.tsx` requires no type guards.
- qd-* CSS custom properties are defined once in `apps/web/app/globals.css` and referenced by both hand-written components and shadcn variants. No duplicate token definitions.
